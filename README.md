
ComfyUI - LoRA the Explorer (Fizgig Port with Server Automation)

LoRA the Explorer — инструмент для эволюционного поблочного поиска оптимальных весов LoRA (перблока) в ComfyUI. Расширение является портом алгоритмов из автономного приложения Fizgig (Apache-2.0), полностью адаптированным под логику работы нод.

💡 Идея метода

Вместо того чтобы вручную крутить ползунки десятков блоков модели, нода генерирует 4 мутировавших варианта поблочных весов. Вы рендерите их одновременно, выбираете лучший вариант, и процесс повторяется. Это позволяет постепенно «вырастить» нужный визуальный эффект (стиль, детализацию, позу) или, наоборот, очистить картинку от артефактов, не разрушая композицию исходного изображения.

🛠️ Главное улучшение: Серверная автоматизация без проводов

В оригинальном порте для перехода к следующему раунду мутаций требовалось копировать длинные строки JSON, использовать промежуточные ноды Pick или замыкать циклы связей, что запрещено в ComfyUI.
Эта модифицированная версия полностью автоматизирована через оперативную память сервера Python:
• Никаких цикличных проводов: Больше не нужно тянуть связи обратно в ноду или вручную копировать текст.
• Автоматический кэш раундов: Сервер на лету запоминает математические веса всех 4-х сгенерированных превью.
• Эволюция в один клик: Чтобы запустить следующий шаг мутаций или намертво запечь результат, достаточно выбрать нужный вариант в выпадающем меню Combo-бокса.

📦 Доступные ноды

1. LoRA the Explorer (Fizgig) — генерирует 4 мутировавших варианта карты блоков на основе выбранного источника.
2. LoRA Block Loader (Explorer) — загружает LoRA и «на лету» (в памяти) применяет сгенерированные поблочные множители к первому фактору весов (работает без SVD-потерь для Kohya, Diffusers, LoKR и LoHa).
3. LoRA Save (Explorer) — окончательно запекает выбранный из кэша вариант в полноценный файл .safetensors, готовый к использованию в любых стандартных загрузчиках на силе 1.0.
4. Checkpoint Scan (LoRA Royale) — вспомогательный сканер чекпоинтов из папки для их последовательного перебора.

🚀 Быстрый старт (Линейный воркфлоу)


Шаг 1: Сборка базовой схемы

Соберите стандартную параллельную сетку для рендеринга 4-х вариантов:
[Нода Explorer] 
   ├──> variant_1 ──> [Block Loader 1] ──> [KSampler 1] ──> Preview Image 1
   ├──> variant_2 ──> [Block Loader 2] ──> [KSampler 2] ──> Preview Image 2
   ├──> variant_3 ──> [Block Loader 3] ──> [KSampler 3] ──> Preview Image 3
   └──> variant_4 ──> [Block Loader 4] ──> [KSampler 4] ──> Preview Image 4
Убедитесь, что все KSampler используют один и тот же сид шума (например, через ноду Primitive), чтобы вы сравнивали влияние блоков LoRA, а не разницу в случайном шуме.

Шаг 2: Первый раунд (Старт)

1. В ноде Explorer установите параметр state_source в значение fresh state.
2. Поле continue_from_variant оставьте в положении None.
3. Нажмите Queue Prompt. Сгенерируются 4 картинки, а сервер автоматически сохранит их структуры весов в оперативной памяти.

Шаг 3: Последующие раунды (Эволюция)

1. Посмотрите на получившиеся изображения. Допустим, вам больше всего понравился результат на Превью 3.
2. В ноде Explorer измените всего два параметра:
	• state_source ──> bootstrap from cache
	• continue_from_variant ──> Variant 3
3. Смените сид шума в KSampler (чтобы проверить устойчивость весов на другом шуме).
4. Нажмите Queue Prompt. Нода мгновенно извлечет SliderState третьего варианта из памяти, примет его за новую базу и построит от него 4 новые точечные мутации. Кэш сервера автоматически обновится новыми результатами.

Шаг 4: Фиксация результата (Запекание)

Когда вы доведете эффект до идеала (например, на шаге 5 вам подошел Вариант 1):
1. Добавьте на схему ноду LoRA Save (Explorer).
2. Выберите вашу LoRA в lora_name и установите save_from_variant ──> Variant 1.
3. Провод block_map подключать не нужно.
4. Нажмите Queue Prompt. Готовый файл .safetensors сохранится в каталог output/fizgig/.

🧬 Поддерживаемые архитектуры моделей

Расширение автоматически считывает метаданные safetensors-файла и классифицирует структуру ключей блоков:
• Klein 9B (включая Diffusers/Flux): 8 double + 24 single блоков.
• Krea 2: 32 блока + слои text fusion.
• Qwen Image 2.1: 32 блока.
• MiniMax H3: 50 главных + 2 рефайнер-блока.

⚠️ Важные диагностические советы

• Картинки ломаются/искажаются при нулевых настройках: Базовое состояние (baseline) унаследовало сильный дрейф предыдущих поколений мутаций. Сбросьте состояние, переключив state_source на fresh state.
• Все 4 превью абсолютно одинаковы:
	1. Проверьте консоль. Если написано MODEL was NOT patched, вы пытаетесь использовать чужую LoRA (например, Qwen LoRA на модели Flux/Klein).
	2. Убедитесь, что провод MODEL в каждом сэмплере идет из своего индивидуального Block Loader, а не напрямую из общего Load Checkpoint.
• Сохранение лица (Qwen Image 2.1): В архитектуре Qwen блоки с 10 по 14 отвечают за сходство лица и черт персонажа. Если вы хотите изменить окружение или позу, но сохранить лицо стабильным, впишите в поле locked_blocks значения: block_10,block_11,block_12,block_13,block_14.

📥 Установка

bash
cd ComfyUI/custom_nodes
git clone https://github.com
Используйте код с осторожностью.
После установки полностью перезапустите сервер ComfyUI (простого обновления страницы в браузере недостаточно, так как сервер должен инициализировать новые Python-модули).
Если вам потребуется интегрировать в это README графическую схему или дополнить его разделом по тонкой настройке силы мутаций (intensity/structure), дайте знать — я подготовлю расширенную версию.
